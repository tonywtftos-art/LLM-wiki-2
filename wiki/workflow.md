# Loop / Graph 設計與反思

![workflow 流程圖](assets/workflow.svg)

## 一句話
整個流程是一張 **graph**：每個方框是一個步驟（節點），箭頭是順序。**紅色虛線是退回邊**：檢查不通過就往回走，形成 **loop**。

## 資訊怎麼流動

```
PDF 原文 ──讀取──▶ 文獻頁 ──整合──▶ 概念頁 ──Query──▶ 簡報大綱 ──生成──▶ HTML 簡報
           ▲                                   ▲                          ▲
        檢查①：對照 PDF                     檢查②：有出處              檢查②③④：對照 wiki
```

**每一層只對照上一層**：
- 檢查①：wiki 對照 PDF
- 檢查②～④：簡報對照 wiki

所以簡報裡的引文和數字只要能在 wiki 找到，就等於已經對照過原文，因為 wiki 這一層已經過檢查①。

## 哪些步驟會重複執行？
| 重複的部分 | 為什麼 |
|---|---|
| 迴圈 A 整段，每篇跑一次 | 概念頁要逐篇累積，第 3 篇才能和前 2 篇比較、找出矛盾 |
| 檢查① 不通過 → 重寫文獻頁 | 引文或頁碼錯了，越早修越好 |
| 檢查②③④ 不通過 → 重寫那一頁（最多 3 輪） | 只改出問題的那一頁，不整份重做 |
| 使用者審閱 → 退回修改 | 人也是 graph 的一個節點 |

## 哪些地方需要檢查或重新生成？
| 檢查 | 位置 | 怎麼檢查 | 不通過時 |
|---|---|---|---|
| ① 引文、數字對照原文 | Ingest 之後 | `tools/check_citations.py`、`tools/check_numbers.py` | 重寫文獻頁 |
| ② 可追溯 | 大綱之後、簡報之後 | `tools/check_slides.py`：每張有 `data-src`；引文、數字、概括說法都要在出處頁 | 補出處或重寫 |
| ③ 聽得懂 | 簡報之後 | 術語第一次出現要用 `<dfn>` 解釋；中文句子不超過 45 字 | 重寫那一頁 |
| ④ 矛盾有標出 | 簡報之後 | 要有一張「矛盾」投影片，提到 Donia 和至少 3 種判斷依據 | 補一頁 |
| ⑤ 架構 | 簡報之後 | 動機 → 每篇文獻一頁（4 個固定欄位）→ 總整 → 共識 → 矛盾（第 2 次執行後新增） | 重新 Query 大綱 |
| 版面 | 簡報之後 | 電腦和手機截圖 | 改 CSS |
| ⓪ 檢查程式本身 | tools/ 改過時 | `tools/selftest.py` 故意放 12 種錯 | 先修檢查程式 |

## 為什麼這樣設計？
1. **錯誤在源頭攔截**：簡報的內容全部來自 wiki。如果 wiki 的引文錯了，簡報一定跟著錯，所以最嚴格的檢查（對照 PDF）放在最前面。
2. **生成和檢查分開**：AI 寫完後，由程式檢查，不讓 AI 自己說「我檢查過了」。
3. **最多 3 輪**：避免 AI 一直修不好卻一直重試；超過就交給人決定。
4. **好答案存回 wiki**：簡報大綱是一次 Query 的結果，存在 [[teaching-outline]]，下次要改簡報可以直接用，不用重新查。

## 反思（第一次實際執行後）
完整紀錄見 [[checks|檢查紀錄]]。

**哪一個節點最常出錯？**
最常出錯的是**檢查節點本身**，也就是檢查程式。第一次執行時，檢查程式出了 3 次錯：
- 數字檢查把 `pp.228, 232` 只讀成 228，而且看不懂原文用英文寫的「Ten interviewees」→ 5 個假警報
- 簡報檢查把 `9.2` 正規化成 `9 2`，找不到 → 假警報
- 修上一個錯時，把頁碼前面的「.」擋掉 → 一次出現 19 個假警報

內容方面，最常出錯的是**寫簡報（⑦）**：第一張就用了「象徵」「實質」卻沒有解釋。另外有兩個問題程式抓不到，是在截圖（⑧）時才被發現：
- 一句沒有出處的「多數人會選 B」
- 引文只節錄一半，旁邊的中文大意卻提到被節錄掉的「15%」

**把檢查往前移到了哪裡？**
- 「沒有出處的概括說法」原本要到 ⑧ 截圖時靠人眼發現，現在**移到 ⑦ 之後的檢查②**，由程式自動抓「多數人、研究顯示、一般認為」這類詞。
- 「引文沒標頁碼」原本檢查①看不到，所以 Hrasky 表格的 7 句引文沒被檢查。現在檢查① 會列出沒標頁碼的引文，**在 ingest 階段就要求補上**。
- 「檢查程式對不對」原本沒有人檢查，現在**在所有檢查之前加了 ⓪ 自我測試**。

**有沒有因此修改 workflow / graph？為什麼？**
有，graph 多了一個節點 ⓪「檢查程式自我測試」。原因：檢查節點是整個 loop 的裁判。裁判錯了，loop 會一直退回、重寫本來沒錯的內容（假警報）；或者讓錯的內容通過（漏抓）。第一次執行時，19 個假警報差點讓 AI 去改 19 頁其實沒問題的投影片。所以檢查程式本身也要被檢查。

## 反思（第二次執行：使用者審稿退回）
完整紀錄見 [[checks2|檢查紀錄（第 2 次）]]。

**哪一個節點出錯？**
這次錯的不是文字細節，而是 **⑥ Query（規劃大綱）**：簡報按主題切，沒有先講「為什麼公司只說不做」，7 篇文獻也沒有各自完整介紹。檢查②③④全部通過，因為它們只檢查**每一頁對不對**，不檢查**整份簡報的架構對不對**。最後是在 ⑩ 被使用者擋下來。

**把檢查往前移到哪裡？**
- 把使用者要的架構寫進 AGENTS.md，並做成**檢查⑤**，放在 ⑦ 之後自動檢查。用新規則檢查舊簡報，會出現 31 個 FAIL，代表這類問題以後不用等到人審。
- 在 ⑥ 加一條規則：大綱需要的內容 wiki 沒有，就**先回 wiki 補一頁**再寫大綱。這次的「為什麼只說不做」就是先補進 wiki，簡報才有出處可追溯。

**有沒有修改 workflow / graph？**
有：
- 檢查節點 ②③④ 變成 ②③④⑤。
- ⑩ 的退回邊分成兩條：只改呈現方式時回 ⑦，架構或內容不對時回 ⑥（再視需要回 wiki 補頁）。

原因：人的審閱最貴，應該只留給程式判斷不了的事，例如內容讀起來合不合理。能寫成規則的，就交給檢查程式。
